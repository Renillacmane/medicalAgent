## Spec: Offline vitals submission — mobile (`specs/offline-vitals-submission-mobile.md`)

### Queue and submit

- [x] When user submits vitals offline (or failed POST), queue in IndexedDB and show "saved offline"
- [x] When online, POST to API; on success normal; on network/server error, fall back to queue + "saved offline"
- [x] Queued vitals use same payload structure as add-vitals-lab-results-api

### Sync when online

- [x] When connectivity returns and app in foreground, queued vitals sync (window `online` event + AddVitalsForm mount)
- [x] Successful syncs remove from queue; failed (5xx, timeout) leave for later attempt
- [x] 401 stops sync; queued vitals remain for next authenticated session

### App lifecycle (mobile-specific)

- [x] **OFFLINE-MOBILE-1** When app is brought to foreground (user returns after connectivity was restored while backgrounded), attempt to drain pending vitals queue
  - Use `@capacitor/app` (add dependency). Listen for `App.addListener('appStateChange')`; when state becomes `active` and `isNativeCapacitor()`, call `syncPendingVitals()`. Wire in root layout or AppShell where native check is available.

### UI feedback

- [x] Add tab shows badge when queued vitals exist (`PendingSyncBadge` on Add nav tab)
- [x] Offline banner when device offline (`OfflineBanner` in AppShell)
- [x] After offline save: "saved offline", can continue or navigate away; no blocking

### Storage

- [x] Pending vitals in IndexedDB (durable); survives app restart
- [x] Same store for PWA and Capacitor (healthia-offline)
